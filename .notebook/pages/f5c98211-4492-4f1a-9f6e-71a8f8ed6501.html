What changed

  • On every read, the app types each message into the right session in the other project:
    • A message whose reply_to names a session running there goes into that session, as it is.
    • Any other message goes to that project's Product as asked, either typed into the running Product or as the prompt of a new one. That board then shows it as a request: what Product files is marked new, and its Approve and commit commits only its own files.
    • A to that names no open project gets a one-line "Not delivered" answer in the sender's session.
  • Each message is typed in once. The app remembers what it delivered by file path plus a hash of the content, in @AppStorage("deliveredMessages"), which is restored before the first read after a relaunch. The message files are never written. Nothing logs a message's title or body.
  • The window never moves: delivery only types into terminals.
  • For the UI task: BoardRequest.from holds the folder of the project that asked, and ProjectModel.waitingOn[session] holds the folder of the project a session is waiting on.
  • docs/architecture.md has a new section, "How a message travels between projects", and AGENTS.md lists it.

Calls I made

  • Routing returns pairs of (session, text), and AppModel only types them in. That keeps the routing testable without a terminal, and it is why the window cannot move.
  • The delivered key includes a content hash, so if an agent reuses a slug like answer.md, the new message still gets through.
  • If the asked project's Product is already on a request, that request stays. Whatever it filed is still marked new, and nothing records who asked.
  • A message with nobody to tell (its project is not open and its sender has gone) is not marked delivered. A later read delivers it once that project is open.
  • The delivered set is never pruned (ponytail: note). It is one short key per message.
